## 1. 引言

### 1.1 项目背景

当前多数校园管理仍依赖纸质流程、独立分散的单业务系统（如仅教务系统、仅一卡通系统）以及微信群、电话等非结构化沟通方式，普遍存在以下痛点：

1. **信息孤岛**：教务、宿舍、后勤、通知等数据分散在不同系统中，彼此割裂，难以形成全局视图。
2. **流程效率低**：调课、报修、请假、场地预约等仍以线下跑腿、纸质审批为主，周期长、易丢失、难追踪。
3. **通知触达差**：重要通知依赖班级群转发，无已读回执，是否触达无法验证，家长对学生在校情况感知弱。
4. **管理决策缺数据**：校领导缺乏校园运行的一手数据看板，管理决策多凭经验，缺乏量化支撑。
5. **家校沟通薄弱**：家长缺少正规、可控的渠道了解孩子的学业、考勤与在校生活。

SmartCampusOS 旨在以「一个平台、多端协同」的方式，将教学、生活、管理、家校四大场景统一起来，成为校园数字化运营的中枢。

### 1.2 产品定位

SmartCampusOS 是一套面向**中小学及职业院校**的一体化智慧校园管理系统，覆盖教务、宿舍与后勤、通知与家校互动、数据可视化四大核心域，并提供考勤门禁、一卡通消费等扩展能力，服务学生、教师、家长、宿管、后勤、安保、校领导及系统管理员等全部校园角色。

### 1.3 产品愿景

**让校园管理有据可依，让家校沟通畅通无阻，让每一位在校人员都能享受数字化带来的便利。**

## 2. 目标与范围

### 2.1 产品目标

1. **提效**：将调课、报修、场地预约等核心线下流程线上化，单流程平均处理时长下降 50% 以上。
2. **打通**：统一用户体系与消息渠道，消除信息孤岛，实现「一人一号、多端同步」。
3. **透明**：为家长提供学生学业、考勤、生活信息的透明可见窗口；为校领导提供校园运行数据看板。
4. **沉淀**：形成校园数据资产，为教学改进与资源调配提供数据支撑。

### 2.2 成功指标（北极星与关键指标）

| 指标 | 目标值（上线后 6 个月） |
| --- | --- |
| 全校师生账号激活率 | ≥ 95% |
| 通知 24 小时已读率 | ≥ 90% |
| 报修工单平均闭环时长 | ≤ 24 小时 |
| 家长端月活跃率（有子女在读的家长） | ≥ 70% |
| 校领导驾驶舱周使用率 | ≥ 3 次/周 |
| 线上流程替代率（目标流程） | ≥ 80% |

### 2.3 本期范围（v1.0）

- 教务管理：课表、选课、成绩、考试。
- 宿舍与后勤：宿舍床位管理、报修、场地预约。
- 通知与家校互动：公告通知、消息中心、家长端。
- 数据可视化：管理驾驶舱、数据大屏、报表中心。
- 基础平台：统一账号、组织架构、角色权限、操作日志。

### 2.4 不包含范围（后续版本）

- 考勤门禁、一卡通消费等硬件联动能力（v2.0 规划，见 4.5）。
- 在线课堂、教学资源库、AI 辅助教学等深度教学场景。
- 财务核算、薪资发放等纯财务系统功能（仅提供消费流水查询接口）。
- 与第三方系统的深度集成（预留标准接口，不在本期实现全部对接）。

## 4. 核心功能需求

**优先级定义：**

- **P0**：v1.0 必须实现，缺失则产品不可用。
- **P1**：v1.0 重要功能，建议实现，可延后至首个迭代。

### 4.1 教务管理

#### 4.1.1 功能清单

| 编号 | 功能点 | 功能描述 | 优先级 | 主要角色 |
| --- | --- | --- | :-: | --- |
| Edu-01 | 学期与教学计划 | 维护学年学期、教学周历、开课计划；学期数据为课表、选课、成绩的基准 | P0 | 教务/教师 |
| Edu-02 | 课表管理 | 排课、调课申请与审批、多视图课表（按班级/教师/教室/个人），支持冲突检测 | P0 | 教务、教师、学生 |
| Edu-03 | 选课管理 | 选课窗口配置、志愿选课、名额限制、抽签/先到先得策略、退选、选课名单导出 | P0 | 教务、学生 |
| Edu-04 | 成绩管理 | 成绩录入（百分制/等级制）、成绩复核申请、绩点计算、成绩单生成与导出、成绩预警 | P0 | 教师、学生、教务 |
| Edu-05 | 考试管理 | 考试安排发布、考场分配、监考安排、成绩录入关联考试场次 | P1 | 教务、教师、学生 |
| Edu-06 | 学籍档案 | 学生基础信息、学籍异动（转班/休学/复学）记录 | P1 | 教务、学生 |

#### 4.1.2 关键需求细则

**Edu-02 课表管理：**
1. 排课支持手动排与自动排（按教师时间、教室容量、课程性质等约束）；排课结果须经冲突检测（教师/教室/班级时间冲突、连排约束），冲突时系统阻断并提示原因。
2. 调课流程：教师发起调课申请 → 教务审批 → 审批通过后自动更新相关方课表并推送通知（学生、涉及教师、涉及教室管理员）。支持「借教室」单独申请。
3. 课表视图：按周/按日切换；学生与教师端支持「我的课表」，显示课程、时间、地点、任课教师（学生端）、上课班级（教师端）。
4. 课表变更须保留历史版本，支持导出 iCal/图片。

**Edu-03 选课管理：**
1. 教务配置选课批次：适用年级/班级、可选课程范围、每人学分上限、起止时间、选课策略（先到先得 / 志愿抽签）。
2. 学生端：查看课程详情（教师、学分、容量、已选人数）、选课/退选，选课结果即时反馈；抽签制在截止后统一公布结果并通知。
3. 冲突规则：与已选课程时间冲突、超出学分上限、超出课程容量时禁止选入并提示。
4. 教务端：实时查看选课人数与热门课程，可手动调剂、批量导入名单、导出选课统计。

**Edu-04 成绩管理：**
1. 教师按教学班录入成绩，支持 Excel 批量导入、草稿保存、提交后锁定。
2. 成绩修改须走审批：教师发起修改申请 → 教务审批 → 留痕（原值/新值/操作人/时间）。
3. 成绩单：支持按学期/学年生成，导出 PDF/Excel；支持 GPA 计算（可配置算法）。
4. 成绩预警：对不及格科目数、绩点低于阈值的学生，自动生成预警名单并通知班主任与家长（需家长授权范围）。
5. 学生端仅可查看本人成绩；家长端仅可查看自己子女成绩。

**Edu-05 考试管理：**
1. 教务发布考试安排（科目、时间、考场、座位号），冲突检测（同一学生同一时段多场）。
2. 监考安排：按教师分配监考场次，教师可查看本人的监考任务，支持调换申请。

### 4.2 宿舍与后勤管理

#### 4.2.1 功能清单

| 编号 | 功能点 | 功能描述 | 优先级 | 主要角色 |
| --- | --- | --- | :-: | --- |
| Dorm-01 | 宿舍与床位管理 | 楼栋/楼层/房间/床位维护，入住、退宿、调宿申请与审批，床位状态可视化 | P0 | 宿管、学生 |
| Dorm-02 | 住宿信息查询 | 学生/宿管查询住宿信息（宿舍号、床位、室友），支持按条件检索 | P0 | 宿管、学生 |
| Dorm-03 | 报修工单 | 报修提交（文字+图片+定位）、派单、处理、验收、评价，全流程状态可追踪 | P0 | 学生、教师、后勤、宿管 |
| Dorm-04 | 场地预约 | 教室/会议室/体育场馆预约、时段冲突检测、审批、使用登记 | P0 | 教师、学生、后勤 |
| Dorm-05 | 水电与设施管理 | 水电抄表记录、异常上报、设施巡检任务（巡检项、结果、异常上报） | P1 | 宿管、后勤 |
| Dorm-06 | 宿舍评比 | 卫生/文明宿舍评比，评分录入与排名公示 | P2 | 宿管、学生 |

#### 4.2.2 关键需求细则

**Dorm-01 宿舍与床位管理：**
1. 宿舍结构支持「楼栋-楼层-房间-床位」四级建模；床位状态含：空闲 / 已入住 / 维修中 / 停用。
2. 入住流程：学生提交入住/换宿申请 → 宿管审批 → 系统分配或宿管指定床位 → 学生确认 → 床位状态更新；支持新生批量导入分配（可按班级/性别/专业规则自动分配）。
3. 退宿：学生申请 → 宿管核对 → 退宿完成；关联宿舍卫生/物品检查项（可选）。
4. 宿管端提供床位分布图（按楼栋/楼层），支持筛选空闲床位与导出住宿名单。

**Dorm-03 报修工单：**
1. 报修单字段：报修人、地点（宿舍/教室/公共区域，支持地图选点或楼栋房间选择）、类别（水电/门窗/网络/设备等）、紧急程度（一般/紧急）、描述、图片（≤9 张）。
2. 工单流转：提交 → 后勤派单（自动按类别路由或手动）→ 维修人员接单/处理 → 报修人验收 → 评价与关闭；紧急工单超时未接单自动升级提醒主管。
3. 状态全程可追踪（待派单/已派单/处理中/待验收/已完成/已关闭），报修人与后勤均可查看；处理过程支持补充进度说明与图片。
4. SLA：一般工单 4 小时内响应、48 小时内闭环；紧急工单 30 分钟内响应、24 小时内闭环；超时系统自动提醒。

**Dorm-04 场地预约：**
1. 预约要素：场地、日期、时段（按校历课表开放可约时段）、用途、人数、审批人（可配置）。
2. 冲突检测：同一场地同一时段不可重复预约；与既定课程占用自动冲突提醒。
3. 流程：提交申请 → 后勤/场地管理员审批（通过/驳回并附原因）→ 申请人确认；支持签到使用与爽约记录（爽约 3 次限制预约 1 周）。

### 4.3 通知与家校互动

#### 4.3.1 功能清单

| 编号 | 功能点 | 功能描述 | 优先级 | 主要角色 |
| --- | --- | --- | :-: | --- |
| Noti-01 | 公告通知发布 | 按范围（全校/年级/班级/宿舍区域/部门）发布公告，支持定时发送、附件、置顶 | P0 | 全部（按权限） |
| Noti-02 | 消息中心 | 统一收件箱：公告、系统消息、业务通知（调课/审批/工单/成绩等），按类型分组 | P0 | 全部 |
| Noti-03 | 已读回执 | 重要通知记录已读状态，未读自动提醒，发布者可查看已读统计 | P0 | 发布者、接收者 |
| Noti-04 | 家校互动 | 家长与班主任/任课教师私信，班级动态发布，家长查看子女在校情况 | P0 | 家长、教师 |
| Noti-05 | 订阅设置 | 用户自定义接收渠道（站内信/App 推送/短信/微信）与免打扰时段 | P1 | 全部 |

#### 4.3.2 关键需求细则

**Noti-01 公告通知发布：**
1. 发布表单：标题、正文（富文本）、附件、接收范围（按组织/班级/角色/标签）、优先级（普通/重要/紧急）、发送时间（立即/定时）、置顶、是否需回执。
2. 「重要/紧急」通知强制推送并单独高亮，发送渠道默认全开（App 推送 + 短信，短信需在渠道配置中开启计费提醒）。
3. 敏感操作类通知（如成绩、处分）须遵循授权范围，仅推送给本人或授权家长。

**Noti-02 消息中心：**
1. 消息类型：公告、系统消息、业务通知（审批结果、工单进展、选课结果、调课提醒、预约结果等）。
2. 消息按「未读/已读」「全部/公告/业务/系统」筛选；支持单条删除与全部已读；已读回执类消息不可删除（仅可标记已读）。

**Noti-04 家校互动：**
1. 私信：家长仅可与班主任及子女任课教师会话；教师端按班级聚合会话；敏感词过滤与审计留痕；支持快速回复常用语。
2. 班级动态：班主任发布班级照片/通知（与公告打通），家长可点赞评论（评论需教师可见可控，可关闭评论）。
3. 家长首页聚合子女核心信息：本周课表、最近成绩、考勤与在校消费（需授权）、班级通知，形成「子女在校一览」。

### 4.4 数据可视化

#### 4.4.1 功能清单

| 编号 | 功能点 | 功能描述 | 优先级 | 主要角色 |
| --- | --- | --- | :-: | --- |
| Data-01 | 管理驾驶舱 | 校领导一页式核心指标看板：在校人数、出勤、报修、预约、消息触达等 | P0 | 校领导 |
| Data-02 | 数据大屏 | 面向展示场景的大屏（教学运行/后勤运行/综合），支持投屏与轮播 | P1 | 校领导 |
| Data-03 | 报表中心 | 可配置报表（课表统计、选课统计、成绩分布、报修分析、场地利用率等）导出 | P1 | 校领导、教务、后勤 |
| Data-04 | 数据权限 | 数据范围按角色与组织树隔离（年级/部门），明细脱敏 | P0 | 系统管理员 |

#### 4.4.2 关键需求细则

**Data-01 管理驾驶舱：**
1. 指标卡片：在校人数、今日出勤率（若有考勤数据源）、未闭环工单数、今日预约场次数、近 7 日通知已读率、选课异常数等。
2. 趋势图：报修工单量（近 30 天）、场地预约热度、成绩分布（按年级/科目）等，支持时间范围切换。
3. 钻取：点击指标可下钻到年级/部门明细，明细页数据按权限脱敏（如成绩分布不展示个人成绩）。
4. 大屏适配 1920×1080 及以上分辨率，支持自动轮播与手动切换。

**Data-03 报表中心：**
1. 预置报表模板，支持时间、范围、维度筛选；导出 Excel/PDF，支持定时发送到指定邮箱（P2）。
2. 报表访问留审计日志；导出文件含水印（含操作人信息）。

## 6. 非功能需求

### 6.1 性能

| 指标 | 要求 |
| --- | --- |
| 常规页面响应 | 首屏 ≤ 2s，查询类接口 P95 ≤ 1s |
| 并发能力 | 支持全校 5000 人在线（按单校部署规模），选课等峰值场景支持弹性扩容（预估峰值 3000 并发写入） |
| 大屏渲染 | 数据大屏 10s 内完成首帧，自动刷新间隔可配置（默认 1 分钟） |
| 推送时效 | 站内信/App 推送延迟 ≤ 30s（非高峰） |

### 6.2 安全与合规

1. **数据安全**：传输全程 HTTPS/TLS 1.2+；存储对身份证号、手机号等敏感字段加密（AES-256）与脱敏展示；密码加盐哈希存储，禁止明文。
2. **未成年人保护**：涉及未成年人个人信息（学生档案、成绩、位置类信息）的采集与展示，遵循最小必要原则；家长端访问子女数据须完成实名关系绑定与授权。
3. **访问控制**：服务端强制鉴权与越权校验；数据范围按组织树与角色隔离；管理员操作全审计。
4. **合规**：满足《个人信息保护法》《数据安全法》及教育行业相关规定；支持数据导出与删除（账号注销）请求处理。
5. **备份与恢复**：每日全量 + 实时增量备份，RPO ≤ 1 小时，RTO ≤ 4 小时。

### 6.3 可用性与稳定性

- 核心服务可用性目标 ≥ 99.9%（年度）；发布采用灰度/滚动发布，支持快速回滚。
- 高峰期（选课、成绩发布、开学季）需提前压测并预留容量；熔断、限流、降级策略覆盖核心接口。

### 6.4 兼容性与多端

| 端 | 说明 | 兼容要求 |
| --- | --- | --- |
| Web 管理端 | 教务/后勤/校领导/系统管理员 | Chrome/Edge 最近 2 个大版本；分辨率 ≥ 1280×720 |
| App / 小程序 | 学生、教师、家长、宿管 | iOS 12+ / Android 8+；小程序兼容微信最新 2 个大版本 |
| 数据大屏 | 校领导展示场景 | Chrome 内核浏览器，支持投屏 |

### 6.5 可扩展性与集成

1. 对外提供标准 REST API 与 Webhook，支持与一卡通、考勤门禁、钉钉/企微等第三方系统对接。
2. 数据字典（年级、专业、场地类型、报修类别等）后台可配置，支持随学校差异扩展。
3. 模块化架构，后续新增模块（考勤、消费、教学资源）不影响核心链路。

## 7. 业务规则与约束

| 编号 | 规则描述 |
| --- | --- |
| BR-01 | 一个学生同一时刻仅允许归属一个班级（学籍异动期间过渡期不超过 3 个工作日）。 |
| BR-02 | 排课/选课/考试/场地预约均须做时间冲突检测，冲突即阻断并给出冲突对象。 |
| BR-03 | 成绩提交后修改必须走审批，任何修改留痕并保留原值。 |

## 8. 技术概览

> 本章为概要说明，详细技术设计以技术方案文档为准。

1. **总体架构**：B/S 前后端分离。Web 管理端 + App/小程序（H5/原生混合）+ 数据大屏三种前端形态，统一接入后端 API 网关。
2. **后端**：推荐微服务（或模块化单体起步，按需拆分）——用户认证、组织权限、教务、宿舍后勤、消息通知、报表统计为核心服务；消息推送走统一推送网关（站内信 + 第三方推送 + 短信）。
3. **数据层**：MySQL（业务数据，主从 + 读写分离）、Redis（会话/缓存/热点数据）、对象存储（图片附件）、OLAP 或汇总表支撑报表与大屏查询；数据仓库按日 ETL 汇总指标。
4. **安全**：网关统一鉴权（JWT）、RBAC 权限模型（角色-权限-数据范围）、敏感字段加密、全链路审计日志。
5. **部署**：支持私有化单校部署与云托管多租户部署；容器化（Docker/K8s）交付，数据大屏可独立部署于展示机房。
6. **扩展对接**：标准 REST API + Webhook，预留考勤门禁、一卡通消费数据接入接口。

## 10. 风险与对策

| 编号 | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| R-01 | 未成年人数据合规要求严、家校授权流程复杂 | 家长端功能受限或延迟上线 | 上线前完成合规评审；家长绑定采用「班主任审核」轻流程 + 留痕 |
| R-02 | 旧系统数据迁移（课表、成绩、宿舍）质量参差 | 数据不准导致信任下降 | 迁移前数据清洗与抽样核对；迁移后提供 1 个月并行核对期 |
| R-03 | 用户习惯改变，师生接受度低 | 激活率/活跃率不达标 | 开学季窗口上线，配套培训与激励（如开学引导任务） |
| R-04 | 选课/成绩发布等峰值流量冲击 | 系统不可用 | 提前压测、弹性扩容、限流降级预案（预案演练纳入 M6） |
| R-05 | 短信等第三方渠道费用超支或稳定性不足 | 通知触达不达标、成本失控 | 推送网关多通道冗余，短信额度预警与预算控制 |
